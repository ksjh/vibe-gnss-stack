# Vibe GNSS Stack

A completely vibe-coded GNSS (Global Navigation Satellite System) data processing stack built with RTKLIB's `str2str`, featuring a web-based dashboard for real-time monitoring and configuration.

This is just an **experiment**, not a production quality application. I advise not to use it without thorough review. 

While trying [rtkbase](https://github.com/Stefal/rtkbase), I thought about adding some features and a more flexible configuration. While some design and architecture ideas are my own, every line of code has been generated by Claude as an experiment to evaluate the current state of *vibe coding*.

The code is likely to evolve, I am not done yet with my experiment.

## Overview

The Vibe GNSS Stack provides a three-layer pipeline for GNSS data:

1. **Input Bridge (str2str)**: Reads the serial GNSS receiver and exposes it as a TCP server
2. **Data Streaming (str2str)**: Filters and distributes RTCM3/NMEA data to multiple outputs
3. **Web Dashboard**: Real-time visualization and configuration interface

## Features

- **Real-time GNSS Data Streaming**: Live NMEA/RTCM3 data via WebSocket
- **Multiple Output Formats**: TCP server, file logging, NTRIP caster
- **Web-based Configuration**: Edit TOML config through the dashboard
- **Systemd Integration**: Automatic service management
- **Process Monitoring**: Status tracking for all managed processes
- **Serial Device Support**: Direct serial port access via str2str input bridge

## Prerequisites

- Linux system with systemd
- Python 3.8+
- RTKLIB (str2str binary)

## Installation

1. Clone the repository:
   ```bash
   git clone https://github.com/yourusername/vibe-gnss-stack.git
   cd vibe-gnss-stack
   ```

2. Run the installer as root:
   ```bash
   sudo ./install.sh
   ```

   This will:
   - Install system dependencies (Python venv)
   - Create a dedicated `gnss` user
   - Set up systemd services
   - Install Python dependencies in a virtual environment

3. Configure your GNSS device in `/etc/gnss/str2str.toml`

## Configuration

The main configuration file is `/etc/gnss/str2str.toml`. Key sections:

### General Settings
```toml
[general]
log_level = "INFO"
log_file = "/var/log/gnss/manager.log"
restart_delay = 5
max_restarts = 0
```

### Input Bridge (str2str serial → TCP)
```toml
[str2str.input_bridge]
enabled  = true
device   = "/dev/ttyUSB0"
baudrate = 115200
port     = 4001
```

### Data Streaming (str2str)
```toml
[str2str.input]
type = "tcpcli"
host = "127.0.0.1"
port = 4001

[[str2str.outputs]]
name = "rtcm3_tcp"
enabled = true
type = "tcpsvr"
port = 9001
```

## Usage

### Starting the Services

1. Start the dashboard:
   ```bash
   sudo systemctl start gnss-dashboard
   ```

2. Access the web interface at `http://localhost:5000`

3. Configure settings through the web UI

4. Start the GNSS stack:
   ```bash
   sudo systemctl start gnss-stack
   ```

### Web Dashboard Features

- **Live GNSS Data**: Real-time position, satellite info, and signal quality
- **Configuration Editor**: TOML syntax-highlighted editor with validation
- **Service Control**: Start/stop/restart GNSS services
- **Process Status**: Monitor running processes and their health
- **Log Viewer**: View application logs

### API Endpoints

- `GET /api/gnss` - Current GNSS state
- `GET /api/config` - Get configuration
- `POST /api/config` - Update configuration
- `GET /api/service/status` - Service status
- `POST /api/service/start` - Start service
- `POST /api/service/stop` - Stop service
- `GET /api/processes` - Process status

## Supported GNSS Data Sources

- Serial devices (via str2str input bridge or direct)
- TCP client/server
- UDP streams
- NTRIP clients
- File input

## Supported Output Formats

- TCP server (RTCM3/NMEA)
- File logging with rotation
- NTRIP caster
- UDP broadcasting

## Troubleshooting

### Common Issues

1. **Serial device permissions**: Ensure the `gnss` user has access to `/dev/ttyUSB*`
2. **Port conflicts**: Check if ports 4001, 5000, 9001 are available
3. **RTKLIB not found**: Install RTKLIB and ensure `str2str` is in PATH
4. **Service failures**: Check logs in `/var/log/gnss/`

### Logs

- Application logs: `/var/log/gnss/manager.log`
- Systemd logs: `journalctl -u gnss-stack` or `journalctl -u gnss-dashboard`

## Development

### Local Setup

1. Create a virtual environment:
   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

2. Run the application:
   ```bash
   export GNSS_CONFIG=str2str.toml
   python app.py
   ```

3. Access at `http://localhost:5000`

### Project Structure

- `app.py` - Flask backend and WebSocket server
- `str2str_manager.py` - Process manager for str2str (input bridge + outputs)
- `templates/index.html` - Web dashboard frontend
- `install.sh` - Installation script
- `uninstall.sh` - Uninstallation script
- `gnss-stack.service` - Systemd unit for the stack
- `gnss-dashboard.service` - Systemd unit for the dashboard
